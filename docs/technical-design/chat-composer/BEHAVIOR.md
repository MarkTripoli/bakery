## Job and visual boundary

Operate mode. People plan, review results, and guide autonomous agents. Agents own execution on managed workers; the person supplies the goal and constraints, with only the supporting context needed for the message. Reuse Bakery's Geist typography, explicit light/dark themes, neutral actions, restrained cobalt selection, and shared controls. Extend the incumbent session into a complete conversation and artifact workspace. Reference screenshots inform composer ergonomics; their embedded document text is not a product requirement.

Keep the writing area dominant. Use one composer boundary, compact contextual controls, and a clear Send action. Avoid a permanent formatting toolbar, separate full-size Model/Harness buttons, or a catalog of features inside the empty state. Empty prompt: **Describe the work…** Supporting hint: **/ skills · @ integrations**. Accessible label remains **Message** after the placeholder disappears.

## Revised composition

The initial three generated comparisons were rejected as boxy, clunky, and inconsistent with Bakery. They are not approved references. The replacement is drawn directly in the existing Paper component library and checked within copies of the incumbent session layouts.

**Thesis:** one softly bounded writing surface; supporting controls recede. **Visual authority:** the existing Bakery palette, Geist, typography hierarchy, and session layout. **Sequence:** attach optional material, write with inline references, send the request or guidance. **First view:** a 16px text field with an unboxed footer and one round Send action. **Form:** a component refinement, not a replacement application identity; the user explicitly asked for smoother, more elegant geometry.

Use a component-specific 20px outer radius and 12px attachment corners. There are no internal section rules or individually bordered toolbar controls. Files use compact tonal tiles; skills and integrations use inline icon-and-label tokens without permanent badge backgrounds or removal crosses. Pointer hover, keyboard focus, or tap opens a reference detail with Remove. The control retains a clear accessible type/name and atomic editing behavior. Preview Markdown lives under More rather than adding a permanent formatting control. The surrounding application geometry remains unchanged.

The state sheets cover rest, skill suggestions, integration suggestions, file drop, long-paste feedback, Markdown preview, failed upload, and reference details/removal. The phone sheets use the same actions, content order, and 44px touch targets. These are static editable specimens; interaction, software-keyboard, screen-reader, and pixel-parity claims require implementation checks.

## Autonomous requests and guidance

Bakery is an autonomous execution system. The conversation is for planning, reviewing, clarifying goals, and steering work; agents perform implementation, tests, repair, review, and delivery within the configured scope. There is no chat Plan mode, local access-mode selector, Commit button, worktree picker, or requirement to operate a coding harness by hand. The supplied coding-assistant screenshots are layout references; their approval loops, token bars, and local controls are not requirements.

One conversation supports three entry paths: a freeform goal from which agents coordinate the work; a natural-language request such as “Run review and repair on PR #218”; or an explicitly selected, versioned saved workflow. These are requests, not separate chat modes. A request only to plan or review stays within that intent. A clear request to execute authorizes the autonomous run without another routine launch confirmation. During execution, new guidance is attached to the active run and applied at its supported checkpoint; it does not silently start a duplicate run or interrupt a committed step. Missing essential context remains a focused question. Routine validation failures and retryable errors are handled by the configured workflow rather than turning each attempt into an approval prompt.

The footer contains **Add context**, optional **Workflow**, **More**, and **Send**. Workflow opens the existing accessible workflow catalog; selection stores its exact version and shows a removable reference in the draft. Natural-language invocation resolves the same identity. Ambiguous names require disambiguation; merely browsing or selecting a workflow does not launch it. Unavailable or incompatible workflows preserve the draft and explain what is missing. No selection is required for a freeform request. **More → Preview Markdown** retains the optional preview. Model/provider/harness policy belongs to task/workflow settings; resolved execution metadata remains available in Activity, without permanent model or effort dials in the composer.

Agent-directed messages use the shared message operation and admission rules. The agent can answer a planning question or start work according to the explicit request and current run context; prose is not a second execution endpoint. Human-only comments remain an explicit collaboration action, not a primary composer mode. Quoted text, screenshots, attachments, and external documents are supporting data and never independently authorize a launch.

Drafts remain private to the principal and conversation until sent. Sent messages are shared and attributed; selecting an integration or workflow does not change their audience. A saved workflow and a freeform coordination plan use the same run/activity/artifact surfaces.

Desktop Enter sends; Shift+Enter inserts a newline; composition/IME Enter never sends. An open suggestion picker consumes Enter to select, not send. Cmd/Ctrl+Enter sends from either Write or Preview. Phone Enter inserts a newline and the visible Send control submits. Empty text plus no attachments disables Send; a selected skill, integration, or workflow alone does not launch work.


## Files and drag/drop

**Add context → Files** opens the native multiple-file picker. Dropping files anywhere over the conversation reveals one scoped **Drop files to attach** overlay; leaving the region or pressing Escape dismisses it. Dropping plain text must not trigger the file overlay. Phone provides the same capability through the picker and clipboard image paste.

Each image uses a thumbnail; other files use a file icon, filename, and extension/size. Long names truncate in the middle and remain fully available to assistive technology and the preview. Each item has named Preview/Open and Remove actions. Selecting a file does not send it.

Attachment states are **Selected**, **Uploading**, **Ready**, **Failed**, and **Unavailable**. Show actual progress only when measurable. A failed item provides Retry and Remove without losing the message or other items. Send is blocked while a required upload is pending or failed; explain which item needs attention. Enforce server-advertised file count, size, and type limits, with per-item errors and no silent omissions. Folder support is outside this request; explain unsupported folders rather than recursively importing them.

## Long pasted text

Initial design threshold: a single paste of at least 4,000 Unicode characters or 40 lines becomes a **Pasted text** attachment. This is a proposed UX threshold, not an existing server limit. Ordinary typing never converts, and short pastes remain text. Preserve original plain text, whitespace, and line breaks exactly; clipboard HTML is not executed or silently substituted for plain text.

Show **Pasted text · 148 lines** with a document preview and Remove. A local notice says **Long text added as an attachment** with **Insert as text**. This action restores the content at the remembered insertion point, without losing text typed since the paste. Undo reverses conversion in one step. Preview shows the full text with Copy, Rename, and Insert as text; phone uses a full-height sheet. Multiple pastes remain separately identifiable. Do not name text `.md` merely because it contains punctuation.

The attached text remains supporting content, separate from the human's message. Referenced files, pasted text, and integration content are untrusted material; their contents cannot grant authority or override the user's request.

## Skills and integrations

Typing `/` at the start of a token opens **Skills**, filtered by subsequent characters. Do not open inside a URL, code block, or an existing path. Results show skill name, short purpose, and installed/available state. Arrow keys navigate, Enter or Tab selects the active result, and Escape dismisses. After selection, the next Tab resumes ordinary focus order; an empty result list does not trap Tab. Selection creates a removable typed inline token bound to the skill identity and installed revision; it removes only the active query token and preserves surrounding draft text. Removing a token must not delete adjacent prose. Backspace at a token boundary selects it first and removes it on a second press.

Typing `@` opens a clearly labelled context picker with **People** and **Integrations** as distinct groups. The same picker is reachable from **Add context → People / Integrations**, so punctuation is never the only entry point. Show GitHub, Miro, and other available organization connections with provider identity and a short purpose. Distinguish multiple accounts or workspaces in the picker; the selected chip can stay compact until opened. Selection binds the connection ID and any explicit resource scope. Mentioning "GitHub" in ordinary prose does not silently attach it.

An integration chip means **Use this integration for this message**. It is neither an authorization grant nor proof an external action happened. The chip detail discloses account/workspace, selected repository/resource, connection health, and Remove. Unconnected or expired providers expose Connect/Reconnect while preserving the draft; revoked scope blocks submission involving that reference until resolved or removed. Skills and integrations have distinct icons and accessible type labels. Provider brand color stays in the mark.

## Markdown

Write is the default and preserves source text. Preview is optional, in place, and returns focus/caret/scroll position to the draft when closed. Support the shared Markdown renderer for headings, emphasis, lists, links, blockquotes, tables, inline code, and fenced code. Use the same renderer for transcript messages and draft preview. Escape raw HTML, reject unsafe URL schemes, and do not auto-fetch remote images in a private draft. Tables and code scroll within their own bounds without horizontal page overflow.

Attachments and typed references remain visible in Preview. They are sent as structured context alongside the original Markdown source, never flattened into display-only chip labels. Previewing never sends or calls an integration. A full rich-text/WYSIWYG editor is not necessary for this behavior.

## Transcript and recovery

Use calm attributed message rows, readable Markdown, compact attachment summaries, and grouped activity disclosures. Keep author/time and the request, guidance, or explicit comment context visible; avoid decorative chat bubbles and per-token animation. Retain scroll position when reading older messages and offer **Jump to latest** for new content. Announce meaningful message/turn state changes politely, never every streamed token.

On send, retain the draft until the server's durable receipt. Distinguish **Sending**, **Sent**, **Queued for agent**, **Working**, and terminal turn outcomes. Failed sends preserve text/context and retry the same client message identity. Offline drafts are **Not sent**; a reconnect alone is not evidence of delivery. Restore protected drafts only to their original principal/conversation; logout or access revocation clears protected caches according to the multiplayer contract.

## Full chat workspace

The full-workspace extension below adds the transcript, media, artifact workspace, remote-preview access, and side-chat contracts to the composer requirements above.

### Workspace composition

**Thesis:** keep the conversation readable while its work can open beside it, expand, or disappear into a small restore control. **Own world:** Bakery's Geist, neutral surfaces, cobalt links, attributed rows, and existing soft composer. **Story:** read the response, inspect the exact artifact, discuss a focused detail, and bring the decision back. **First viewport:** 208px navigation, 768px conversation, and a 464px workspace within a 1440px desktop; the preview sits above an anchored side chat. **Form:** an extension of the approved session composition, not a new visual identity.

The context trail, session title/status, participants, and Search remain outside the scrolling transcript. Each conversation keeps its own private composer draft. Streaming status, tool activity, queued messages, and errors are explicit; an activity disclosure retains source/evidence instead of exposing hidden model reasoning. Copy Markdown, discuss a message/selection, and More are keyboard/touch accessible as well as pointer accessible. New content does not pull someone away from an older message. Jump to latest restores follow mode. Search locates messages and opens their surrounding context; it preserves the current draft and scroll return point.

Only bounded objects such as attachments, code, and media receive a surface. Messages stay on the page with identity, time, and readable prose. The central reading measure stays at or below 720px when the workspace is minimized.

### Full Markdown and media rendering

Use one renderer for message bodies, draft preview, artifact Markdown, and side-chat bodies. The baseline is CommonMark plus GFM: headings 1–6, paragraphs and hard breaks, bold/italic/strikethrough, ordered/unordered/nested lists, task lists, links/autolinks, blockquotes, rules, tables, inline code, and fenced code. Footnotes are an explicit extension. Preserve original source for copying/editing. Rendering is not an execution or approval path; completed task-list items inside a message are authored content rather than independently verified checks. Interactive task-list edits, if added, use an explicit edit operation.

Code blocks expose language, Copy, and optional wrapping. Long blocks collapse at a bounded height with Show more; horizontal scrolling stays inside the block. Syntax colors have authored light/dark maps. Tables retain actual header/cell semantics and a keyboard-focusable overflow region at narrow widths; no horizontal page overflow. Long unbroken URLs, RTL prose, partial streamed fences, and malformed Markdown degrade to readable source without dropping content. Math and Mermaid are possible later renderer extensions, not included in the baseline merely because the input is Markdown.

Images show a bounded thumbnail, alt text when supplied, dimensions, and an Open action. The workspace viewer supports fit, 100%, zoom, download, and image-anchored discussion. Unknown binary formats use filename/type/size plus authenticated download; do not pretend a preview exists. File and artifact names remain distinguishable from message text.

Video uses the platform player with a poster, play/pause, seek and elapsed/duration, volume/mute, playback rate, captions, and full screen. Picture-in-picture is available where the platform supports it. Default to paused; never autoplay audio. Offer a transcript when a caption/transcript asset exists, with timestamp links to seek. Missing captions are disclosed, not invented. Preserve playback position across expansion/minimization and retry. Only one player is audible at a time. A paused/failed/reconnecting state is never labeled Live. Reduce data usage by fetching metadata/posters before playback, loading offscreen media on demand, and releasing inactive decoders.

The existing [artifact contract](../14-artifacts.md) still limits each stored version to **10 MiB**, validates MIME/bytes, authorizes content reads, and supports bounded byte ranges. This design does not introduce unlimited video uploads or an object-store bypass. An oversized upload names the limit and preserves the draft; larger media needs a separately approved storage change. Videos are played from authorized artifact content, not injected as arbitrary iframe embeds. Third-party video links stay links until an explicitly supported provider can safely render them.

### HTML previews and artifact workspace

An HTML attachment can show a small static thumbnail in chat with filename and revision. **Open in workspace** opens that exact version. **Preview / Code**, revision selection, download, provenance, and contextual discussion stay available in the artifact toolbar or its named menu. The full workspace can also display Markdown, text/code, images, video, patches, and logs using their shared viewer contracts. Selecting another artifact does not silently jump to its newest revision. A newly published version offers **New revision available**; an older or outdated comment keeps its original target.

Static HTML is sanitized and displayed in an isolated, sandboxed document. It has no Bakery cookies, bridge, top-level navigation, ambient credentials, or implicit network access. Links and active content cannot issue Bakery operations. View source remains available if rendering fails. Inline HTML in an ordinary Markdown message remains escaped; an HTML artifact preview is a distinct, explicit capability. The preview's own light/dark theme remains independent of the Bakery chrome.

**Load live app** opens a picker for an authorized preview environment or remote simulator. A static rendered file is labeled **Static HTML · Revision N**; a connected running app is labeled **Live app** with its environment/worker and current connection state. The two must never be conflated as evidence that a build ran. Open in browser is a separate action for an authorized environment URL.

### Remote app and simulator

The picker lists only environments and workers visible to the current person and session. It includes type, name, online/available state, and the explicit **Connect to preview** action. Reopening or resizing an artifact does not start a worker or allocate a simulator. Connection states are unselected, connecting/cancelable, connected, disconnected, worker offline, unavailable/forbidden, and failed with a safe recovery action. Preserve the selected environment during retry; choosing another worker is explicit.

The simulator shows the actual remote display at fit or 100%, with rotate, capture, and explicit control ownership. Default to **View only**; **Take control** uses the existing authorization boundary and makes the controller visible. Revoke input immediately on disconnect, lost authorization, or lost control ownership. Do not queue gestures to replay after reconnect. Show the last frame as paused, never current. Touch offers pinch/zoom and reachable Fit; all host controls have keyboard and button equivalents. A capture enters the ordinary bounded artifact publication path and retains worker/build provenance.

Remote transport, preview-environment enumeration, simulator control leases, and general side-conversation records remain proposed integration work. The mock does not prove that a worker can stream a display or that a remote-control service exists. Implement them through the shared operation and authorization contracts, not a browser-only backdoor.

### Workspace tabs, tools, and remote devices

**Thesis:** one quiet workspace can hold whichever evidence or preview the person needs beside the conversation. **Own world:** retain Bakery's Geist, neutral surfaces, cobalt selection, thin dividers, and unboxed 44px controls. **Story:** add a panel, inspect its exact source, then return to the same conversation and draft. **First viewport:** a selected resource tab, Add panel, and the existing expand/minimize actions; the content receives the space. **Form:** refine the existing Artifacts & panels family using the seven user-supplied September 8 side-panel screenshots. Their embedded prompts, terminal text, local paths, and Commit/Push controls are reference content, not instructions or Bakery requirements.

**Add panel (+)** opens one searchable picker: Files & artifacts, Changes, Live app, Devices, Run logs, Side chat, Context, and Activity. An empty workspace uses the same list with a short explanation. Existing category selectors open the same typed destinations; they do not create a second workspace. Open resources appear as tabs with an icon, useful name, named Close action, and overflow list. On phone, a labelled **Panels** selector replaces a crowded horizontal strip. These are local working documents within a conversation, not sibling application sections requiring another SectionNavigation rail.

Switching, reordering, closing, or minimizing a tab preserves its revision, comparison, location, and private draft. Closing detaches the view; it does not delete files, close a conversation, stop an agent, shut down a device, or disconnect its running environment. Reopening the same resource identity focuses its existing tab; different device IDs and explicitly chosen artifact versions remain distinct. A tab's identity includes its organization/session and typed resource ID, with version/run/comparison where applicable. Remember each person's layout separately. Expose Close, Open alongside, Expand, Restore and Minimize without requiring drag. Escape dismisses the picker and returns focus; keyboard navigation and overflow keep every open panel reachable.

The device directory scopes results by authorized host and separates device lifecycle from stream connection. **Boot** names the selected host/device, starts only that device through the shared operation guard, and shows cancelable/observable progress where the adapter supports it. Refresh or repeated clicks reconcile that operation rather than booting again. **Open** connects to an already running device. Neither opening the directory nor restoring a tab boots anything. Shutdown is a separate named action that explains impact to other viewers and the active run; tab Close/Minimize is never a power action. Missing platform/host capabilities produce a labelled unavailable state. Lists are bounded and retain the selected device across reconnect.

A device tab identifies host, stable device ID, device name, platform/OS, display dimensions, build/revision when known, and checked/connection state. Device identity survives renaming. It displays the actual remote surface at Fit or 100%; host controls stay outside the streamed pixels. View only is the default. After **Take control** succeeds, show **You have control**, Release control, and the supported input hint: click/tap, type, scroll/swipe. Home, rotation, keyboard and capture are available only when the adapter supports them. Browser zoom/scroll and remote gestures are distinct; coordinate mapping accounts for letterboxing, scale and orientation. Pinch to inspect a remote screen must not silently send a device gesture. Losing focus/control, revocation or disconnect clears pressed keys/pointers and stops input without replay after reconnect. A stale frame is visibly paused.

Their screenshots show an iOS/Android directory, Boot/Open actions, separate device tabs, and a streamed phone with interaction hints. Before implementing Bakery's remote adapter, inspect that plugin's source and licensing, host discovery/device lifecycle, streaming and input transport, coordinate conversion, reconnect, control ownership, authentication and shutdown behavior. Reuse verified parts that fit Bakery's shared authorization and worker lifecycle. The source location, remote host and protocol are not yet verified in this task; no protocol, SDK or transport choice is inferred from the images. Access details can be supplied when that implementation slice starts. Do not create a replacement streaming service merely to match a mock.

Implementation must prove tab/focus/draft restoration; large-file/diff/log coverage; cross-tenant and linked-artifact access; host/device identity; duplicate Boot reconciliation; multiple-device tabs; viewport/orientation input mapping; explicit control handoff; input release on failure; and Close versus Disconnect versus Shutdown. The existing phone/desktop, keyboard, 44px target and reduced-motion checks still apply. These are additional design contracts; their runtime operations/read projections must be reconciled with the described catalogs before implementation.

### Side chats and context

Start a side chat from a message, selection, artifact, or **New side chat**. Its heading names the subject and scope; its audience is **Shared with the session**. Artifact discussions reuse version-pinned roots/replies and typed anchors from the [multiplayer](../07-multiplayer.md) and [artifact](../14-artifacts.md) contracts. General side chats require a linked conversation identity; do not disguise a new record type as an existing artifact comment. A live-draft discussion and an immutable-revision comment retain their distinct anchors under [collaborative documents](../20-collaborative-documents.md).

Each side chat has independent history, unread state, scroll position, and a private draft. Sending a question or guidance uses the same shared message operation and admission/concurrency rules as the main chat; opening the panel never starts an agent. Artifact-side guidance retains its immutable anchor and joins the parent work context. Human-only comments remain an explicit collaboration action. The mocked agent reply represents a request in that thread, with earlier context outside the shown viewport.

**Share summary in main chat** prepares an editable draft with the summary and exact thread/artifact references. The person sends it explicitly; opening a panel, resolving a comment, or receiving an agent answer does not automatically post a summary or alter main-thread context. Sending a summary does not resolve comments. Changing an artifact revision never silently remaps an ambiguous anchor; show Outdated and retain View original.

### Resize, dock, expand, and minimize

The right workspace and its side-chat split each have a visible divider on hover/focus and an expanded touch target. Dragging resizes continuously; pointer capture ends on release or cancellation. Desktop defaults to a 464px workspace; constrain it to at least 360px while preserving at least 480px of useful conversation width. When both cannot fit, use a focused workspace view instead of crushing either pane. The expanded state fills the work area and offers **Restore split** and **Back to conversation**. Expanding the side chat gives it the same focused treatment.

Dragging an artifact or side-chat tab to the right edge reveals one **Open alongside chat** drop target. Drop docks the existing item; it never duplicates or sends content. Escape cancels and restores the prior layout. External file drops retain the composer attachment behavior above. Nested drop handlers must distinguish files from internal artifact/thread references so a tab drag cannot become an upload. Every drag action also exists as a named Open alongside / Expand / Restore / Minimize menu action.

**Minimize workspace** removes the entire right pane. **Workspace** in the session header restores its previous tabs, split ratio, revision, and scroll positions. Minimized side chats occupy a compact shelf inside the workspace; drafts/unread counts remain intact. Minimize does not delete a thread, stop a job, disconnect a live service, or mark messages read. Hidden media pauses unless the person deliberately enabled supported background playback; expensive hidden previews suspend rendering. Disconnect remains explicit.

Use an accessible separator with its orientation and current/min/max values. Arrow keys resize, Shift+Arrow takes a larger step, Home/End reach bounds, and Enter toggles the prior minimized/open state. Dragging to the collapse boundary previews the resulting dock before release; it must not collapse unexpectedly during an ordinary resize. Persist layout per person/device profile, clamp it when the viewport changes, and keep it out of shared conversation content. Escape returns focus to the initiating control; full-screen phone views have a visible Back/Minimize action.

At sheet widths, the main chat is one column; the Workspace shelf opens a full-width artifact route or a focus-managed sheet. The expanded/full-height and minimized states use the same reachable controls as drag handles. At pane widths, use Bakery's 56px compact navigation and allow two panes only when their minimum useful widths fit. At 200% zoom, reflow to the appropriate focused layout. Coarse controls remain 44px, including video controls and workspace menus.

Use the existing 180/240ms local/sheet timing and reduced-motion policy. Preserve a visible first frame during transitions. The memorable interaction is making room for the work without losing the place in the conversation, not animating every incoming message.

## Linked work, changes, and execution activity

**Thesis:** every working conversation has a visible work anchor and a navigable evidence trail. **Own world:** inherit the same neutral Bakery surfaces, Geist, cobalt links, aligned rows, and soft composer. **Story:** open the linked issue or review, inspect the exact changes, then follow the responsible agent and workflow step. **First viewport:** linked Jira/PR context remains in the 56px conversation header; Changes, Context, and Activity use the existing right workspace. **Form:** extend the existing conversation; the expanded activity view separates delegation, calls, and workflow position into aligned panes. All sample links, SHAs, counts, statuses, agents, and timings are synthetic.

### A work anchor for every chat

A freeform conversation can begin immediately. Before autonomous execution starts, agents resolve or create an authorized **open Jira issue, open pull request, or open merge request** as part of intake and show that anchor in the header. The person is not required to create or choose a ticket before discussing a goal. When no authorized target can be resolved, ask for the missing target; do not fabricate a link or broaden access. Side chats inherit the parent work anchors and may add an explicit secondary reference. This is a new chat requirement; it does not retroactively claim that all existing Bakery tasks already have an external ticket or review.

The header shows the primary issue/review identity and status, plus the current open PR/MR when present. The Context panel holds the complete set. The picker searches connected sources, filters to open items by default, identifies provider/account/project/repository, and supports a selected item that is outside the current cursor page. A draft PR is still identified as Draft, not Ready for review. No results, loading, inaccessible source, expired connection, and no open links have explicit recovery. Connect source belongs to Integrations; selecting an item does not create a ticket, post a comment, or start execution.

Revalidate the primary anchor when admitting a new execution request. If it was closed or merged, retain history and its exact identity/status; offer **Link open work** before new execution. Never silently replace the primary link, reopen external work, or erase a completed conversation. Provider outages show the last known state and checked time; an unverified state is not labeled Open. A revoked link is an access-safe unavailable row. Removing the last open anchor requires a replacement before new execution. Linking a PR/MR is supported without requiring an unrelated issue as well.

The linked-work list includes Jira details, review request, repository and branch, current candidate, checks and review findings, artifact versions, workflow run, and agent sessions. Show source and freshness; incomplete collections use Load more and a coverage notice. Open internal details retains chat draft/scroll and browser history; a separate external action opens the original provider URL. Links preserve organization, repository, task, exact version/run, and permitted audience. They never grant access or automatically copy private content into a provider. Jira and GitLab adapters remain requested integration work where absent; the design is not proof those connectors are implemented.

### Git diff

Changes opens a read-only Git diff for the selected repository and exact **base SHA → head SHA**. Distinguish PR/MR comparison, a saved patch artifact, and a worker working-tree snapshot. Never label unsaved workspace edits as a committed PR diff. Show review identity, branch, source/freshness, changed-file count, additions/deletions, and file status. A new head offers **New revision available**; refreshing is explicit and invalidates viewed markers tied to the old pair.

The file tree/list supports search, next/previous changed file, viewed state for this comparison, and collapsed folders. Unified and split modes share line/side anchors. Code uses line numbers and explicit +/− markers as well as semantic color; whitespace mode and wrapping are available. Show bounded hunks with Expand context; virtualize large diffs without claiming omitted lines were checked. Phone defaults to unified with a Files picker and horizontal scrolling contained within code.

**Discuss selection** starts an anchored side chat or inserts a reference into the current draft. Its identity includes repository, base/head pair, old/new side, path, and line range. Publishing a provider review/comment is a separate explicit operation. Renames, deleted/added files, binary/image changes, empty diff, too-large/incomplete coverage, unavailable content, and outdated anchors have truthful fallbacks; Open source/Download patch preserve exact provenance. Binary files do not get fabricated textual hunks. Merge/approve controls remain in their existing authorized review flow.

### Compact run activity

### Agents, call stack, and workflow stack

Activity is execution telemetry, never hidden reasoning. Show the parent agent and the sub-agents it actually delegated to, their task/repository, status, elapsed time, attempt, parent/dependency relationship, and produced artifacts. Running, queued, waiting for a dependency/person/provider, completed, failed, canceled, and unknown are distinct. A parent waiting for children is not completed. Selecting a child opens its own recorded activity/output and the containing workflow step without flattening sibling work into a false sequence.

The **Call stack** is the recorded causal path for the selected agent/span: parent delegation → agent operation → model/tool call. Show action name, timing, outcome, source, run/step/attempt correlation and safe fault; link to authorized output artifacts for details. Parallel sibling calls remain separate. A durable wait/retry is a linked attempt, not an in-memory stack frame kept alive across restarts. Adapters that report only top-level lifecycle events show **Internal calls unavailable**. Missing or dropped spans show a partial-trace notice; do not infer internal calls, model thoughts, arguments, output, or progress from message prose. Raw inputs/outputs and secrets are not default telemetry.

The **Workflow stack** shows the pinned workflow or coordination-plan revision, parent run, nested group/sub-workflow, current step, and logical attempt. It depicts actual dependencies and parallel branches with a join, not a percentage guessed from step count. Selecting a step reveals status, input/output artifact references, assigned agent/worker, checks, and prior attempts. A blocked step states the dependency and links to it. With no saved workflow, label the immutable coordination plan and retain the same navigation. Open workflow goes to the existing Workflow studio run view and its pinned definition; viewing never edits the running plan.

Keep selected span, selected agent, and selected workflow step mutually navigable while preserving independent filters. Follow active work is explicit; browsing older activity freezes selection until Resume following. Use server sequence/cursor order, source timestamps, and completed durations; reconnect does not reset durations or imply success. A disconnected stream freezes the last snapshot with a timestamp. Accessible tree/list and textual dependency summaries accompany the visual graph. Arrow-key navigation, Enter-to-inspect, and focus return work on both themes; phone presents one focused drill-down with 44px controls.

Minimize/restore preserves the selected repository/comparison/agent/step and scroll. Expanded Activity uses three readable panes for agent hierarchy, selected call path, and workflow position. Shared operations own cancellation/retry/continuation and their effects; merely selecting, expanding, or restoring an item cannot restart a job or allocate a child agent. The existing [observability contract](../06-workflows-delivery-and-acceptance.md#observability-evidence-usage-traces-and-evaluations), [coordination contract](../06-workflows-delivery-and-acceptance.md#workflow-ownership-and-multi-repository-work), and [ticket links](../10-tickets.md) supply the execution boundaries.
